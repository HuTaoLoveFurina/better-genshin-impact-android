# bgia — Авто-пропуск сюжета Genshin Impact для Android

> Порт модуля `AutoSkip` из [BetterGI](https://github.com/babalae/better-genshin-impact), выпущенный под открытой лицензией **GPL-3.0**.

Язык / Language：
[简体中文](./README.md) · [English](./README/readme_en.md) · [繁體中文](./README/readme_tc.md) · [日本語](./README/readme_ja.md) · [한국어](./README/readme_ko.md) · [Русский](./README/readme_ru.md)

Telegram-группа：[@bettergi_for_android](https://t.me/bettergi_for_android)

Скрипт авто-пропуска сюжета Genshin Impact на базе **ADB-захвата экрана + симуляции касаний**, логика перенесена из модуля `AutoSkip` проекта [BetterGI](https://github.com/babalae/better-genshin-impact).

Без root, без инъекций, без доступа к игровой памяти — только «скриншот → распознавание → `input tap`», что эквивалентно тапам человека.

Поддерживается: **официальный / Bilibili / международные** серверы Genshin Impact, а также **облачный Genshin** (Китай и международная версия).

## Как это работает

```
adb screencap  ──►  обрезка области 16:9  ──►  сопоставление шаблонов + OCR  ──►  решение  ──►  adb input tap
```

Каждый кадр обрабатывается в следующем приоритете (как в BetterGI):

| # | Сцена | Действие |
|---|---|---|
| 1 | Экран свидания | Тап по кнопке «Пропустить» |
| 2 | Варианты диалога | Сначала восклицательный знак; иначе OCR читает текст варианта и решает по правилам |
| 3 | Воспроизведение | Тап по безопасной зоне для ускорения диалога |
| 4 | Чёрный экран (катсцена) | Тап раз в секунду для продвижения |
| 5 | Всплывающее окно | Тап по кнопке закрытия вверху справа |
| 6 | «Нажмите в любом месте, чтобы продолжить» | Авто-тап при появлении подсказки (см. `click_continue`, напр. сюжет Фонтейна) |

Решение по варианту — цепочка из 5 уровней приоритета:
**пользовательские приоритетные слова → встроенные приоритетные слова → чувствительные слова (пауза) → оранжевые ключевые варианты → стратегия отката (первый/последний/случайный)**

## Установка

```bash
# 1. Установите Android Platform Tools (даёт adb)
sudo apt install android-tools-adb        # Debian/Ubuntu/Kali
# macOS: brew install android-platform-tools

# 2. Создайте виртуальное окружение и установите зависимости
python3 -m venv .venv
.venv/bin/pip install -r requirements.txt
```

> **Пользователям Kali / Debian 12+**: в этих системах включена защита PEP 668; прямой `pip install`
> выдаёт `externally-managed-environment`. **Используйте виртуальное окружение, как выше**;
> не добавляйте `--break-system-packages` (это загрязняет системный Python и может сломать apt).
> Если venv отсутствует, сначала выполните `sudo apt install python3-full python3-venv`.

После этого все команды запускайте через `.venv/bin/python`, либо сначала `source .venv/bin/activate`
(тогда работает `python`), а `deactivate` — для выхода.

## Кроссплатформенность

Проект поддерживает **Linux / macOS / Windows**, а также **локальный запуск на рутированных Android-устройствах** (без ПК).

### Windows

1. Установите Python 3.10+ (отметьте «Add to PATH»).
2. Скачайте [Android Platform Tools](https://developer.android.com/tools/releases/platform-tools),
   добавьте папку с `adb.exe` в системный `PATH`, либо поместите `adb.exe` в корень проекта / `platform-tools/`
   (скрипт найдёт его автоматически).
3. Используйте `bgia.bat` (то же меню, что и `bgia.sh`):
   ```bat
   bgia.bat
   ```
   Или напрямую из командной строки:
   ```bat
   .venv\Scripts\python.exe -m bgia.cli run
   ```

### Рутированное Android-устройство (локальный режим shell)

Запуск прямо в **Termux (root) / Magisk-терминале** на телефоне; скриншоты и тапы идут через
`/system/bin/screencap` и `/system/bin/input` — **без ПК, без проброса adb**.

1. Установите Python и зависимости в Termux (в Termux есть `clang`/`libc++`):
   ```bash
   pkg update && pkg install python clang libc++ make
   python -m venv .venv && .venv/bin/pip install -r requirements.txt
   ```
2. Запуск от root (иначе `screencap` / `input` не получат доступ к экрану):
   ```bash
   su
   cd /data/data/com.termux/files/home/bgia   # путь к проекту
   .venv/bin/python -m bgia.cli run --local
   ```

> Локальный режим пропускает подключение adb и напрямую вызывает системные `screencap -p` / `input tap`.
> Если скриншоты не работают, убедитесь, что выполнили `su` и `/system/bin/screencap` существует.

## Подключение телефона

**USB:** включите «Параметры разработчика → Отладка по USB», подключите и нажмите «Разрешить» на телефоне.

**Беспроводное (Android 11+):** включите «Параметры разработчика → Беспроводная отладка» и выполните сопряжение по коду:

```bash
adb pair 192.168.1.20:37xxx      # введите код сопряжения, показанный на телефоне
adb connect 192.168.1.20:5555
```

**Беспроводное (Android 10 и ниже):** сначала один раз `adb tcpip 5555` по USB, затем `adb connect <IP>:5555`.

Проверка подключения:

```bash
python -m bgia.cli devices
```

## Подготовка шаблонов

Скрипт использует несколько UI-шаблонов. Исходные шаблоны не распространяются с репозиторием, поэтому
**один раз захватите их со скриншотов своего устройства** (это также адаптирует их к различиям UI между серверами).

Зайдите в любую сцену диалога в игре, затем:

```bash
# Сделать кадр
.venv/bin/python tools/grab_template.py shot        # создаёт shot.png

# Интерактивно выбрать область и сохранить (нужны GUI + opencv-python, не headless)
.venv/bin/python tools/grab_template.py pick --name icon_option.png

# Или измерить пиксели в просмотрщике и сразу обрезать (без GUI, рекомендуется)
.venv/bin/python tools/grab_template.py crop --rect 1150,470,36,36 --name icon_option.png
```

Инструмент автоматически нормализует обрезки к базе **1920×1080** перед сохранением в
`assets/1920x1080/`, поэтому смена телефона или разрешения не требует повторного захвата.

Необходимые шаблоны (при отсутствии работают с деградацией, без падений):

| Файл | Содержимое | Влияние при отсутствии |
|---|---|---|
| `icon_option.png` | Иконка пузыря слева от вариантов | Невозможно найти варианты; деградация до продвижения |
| `icon_exclamation.png` | Иконка восклицательного знака для ключевых вариантов | Теряется приоритет восклицательного знака |
| `stop_auto.png` | Кнопка «Автовоспроизведение» вверху слева | Статус воспроизведения через OCR |
| `hangout_skip.png` | Кнопка пропуска на экране свиданий | Свидания не пропускаются авто |
| `page_close.png` | Кнопка закрытия вверху справа для всплывающих окон | Всплывающие окна не закрываются авто |
| `icon_click_continue.png` | Треугольник/стрелка «нажмите, чтобы продолжить» внизу | Деградация до чисто пиксельного поиска формы (см. «Режим только скриншоты») |

## Использование

```bash
# Самопроверка: разрешение, пакет, область рендера, шаблоны, OCR
.venv/bin/python -m bgia.cli check

# Запуск
.venv/bin/python -m bgia.cli run

# Частые комбинации
.venv/bin/python -m bgia.cli run -c config.yaml          # использовать файл конфигурации
.venv/bin/python -m bgia.cli run -w 192.168.1.20:5555    # беспроводное подключение + запуск
.venv/bin/python -m bgia.cli run -m last                 # приоритет последнего варианта
.venv/bin/python -m bgia.cli run --debug -v              # отладочные скриншоты + подробный лог
```

Остановка — `Ctrl+C`.

## Конфигурация

Скопируйте `config.example.yaml` в `config.yaml` и отредактируйте. Ключевые пункты:

```yaml
option_mode: first          # стратегия вариантов first/last/random/none
before_choose_delay: 0.0    # поставьте 2~3с, если хотите послушать реплики
custom_priority:            # пользовательские приоритетные варианты
  - "Продолжить"
pause_keywords:             # пауза при совпадении, чтобы не тапнуть расходные варианты
  - Выйти из секретной области
  - Купить
interval: 0.6               # облачный Genshin (стриминг): лучше 0.8~1.0
```

## Примечания по серверам

| Сервер | Пакет |
|---|---|
| Официальный | `com.miHoYo.Yuanshen` |
| Bilibili | `com.miHoYo.ys.bilibili` |
| Международный | `com.miHoYo.GenshinImpact` |
| Облачный (Китай) | `com.miHoYo.cloudgames.ys` |
| Облачный (Intl) | `com.miHoYo.cloudgames.genshinimpact` |

Пакет определяется автоматически или принудительно через `-p`.

**Облачный Genshin:** картинка — видеостриминг с размытием кодирования и задержкой сети.
Поднимите `interval` до `0.8~1.0` и опустите `template_threshold` до `0.72~0.75`. Чёрные полосы стрима обрезаются авто.

**Адаптация под вырез/полный экран:** на не-16:9 экранах (20:9 и т.п.) игра центрируется с боковыми
безопасными зонами; скрипт сам находит истинную область 16:9 и проецирует в неё все координаты,
без ручной настройки.

**Адаптация разрешения / DPI / масштаба:** скрипт автоматически подстраивается под любые особенности
телефона, без ручной настройки:
- **Разрешение:** все шаблоны/ROI масштабируются в рантайме как «ширина рендера ÷ 1920»; базовые
  шаблоны 1920×1080 работают для 720p/1080p/2K; область рендера определяется каждый кадр
  (обрезка чёрных краёв + схождение 16:9), не захардкожено.
- **DPI / масштаб (`wm density`, `wm size` Override):** `screencap` возвращает реальное разрешение
  дисплея (физические пиксели), а `input tap` использует логические пиксели `wm size`. При расхождении
  из-за масштаба DPI скрипт кэширует отношение «размер скриншота ÷ размер дисплея» и автоматически
  преобразует координаты тапа, устраняя системный сдвиг.
- Поэтому смена телефона, масштаба дисплея или разрешения в игре не требует повторного захвата шаблонов.

## FAQ

**Варианты не распознаются** — выполните `check`, чтобы убедиться, что шаблоны готовы; опустите
`template_threshold` до `0.72`; если всё равно не работает, экспортируйте скриншоты в `debug/` через
`--debug` и сверьте шаблоны с UI вашего устройства (на разных серверах чуть отличается; перезахватите).

**Сдвиг позиции тапа** — неверно определена область рендера; выполните `check` и сверьте номера области
с реальным экраном; убедитесь, что игра в альбомной ориентации и на переднем плане. Если меняли масштаб
дисплея (`wm size` / `wm density`), скрипт авто-преобразует по физическому/логическому отношению; если
всё равно смещено, выполните `adb shell wm size reset` и `adb shell wm density reset` для сброса.

**Скриншоты медленные** — на некоторых устройствах `screencap` медленный; скрипт уже предпочитает
«сырой» пиксельный конвейер (быстрее PNG). Немного поднимите `interval`.

**OCR недоступен** — выполните `.venv/bin/pip install rapidocr onnxruntime`. Скрипт работает и без него;
варианты деградируют до тапов по позиции.

**Режим только скриншоты (чисто пиксельный запасной вариант)** — даже без шаблонов или OCR скрипт
распознаёт варианты и подсказки продолжения чисто пиксельным анализом:
- **Поиск вариантов:** сканирует экран на «закруглённые тёмные полосы темнее окружения» (общая визуальная
  черта всех UI вариантов Genshin) и тапает самую верхнюю для последовательного продвижения. Работает для
  обычных пузырей, вариантов с иконкой шестерёнки, списков записей и т.п.
- **«Нажмите в любом месте, чтобы продолжить»:** определяет форму треугольника/стрелки внизу по центру
  (чистый поиск формы, шаблон не нужен).
- Это финальный запасной вариант при отсутствии шаблонов/OCR, гарантирующий отсутствие тупика в любой среде.

**pip `externally-managed-environment`** — PEP 668 в Kali/Debian 12+; используйте виртуальное окружение
из раздела Установка. Имя `python3-xyz` в ошибке — лишь плейсхолдер, не реальный пакет.

**`rapidocr-onnxruntime` не устанавливается** — этот старый пакет требует Python `<3.13`. На Python 3.13+
используйте `rapidocr>=2.0` (уже в requirements.txt); код совместим с обоими поколениями. При первом
запуске автоматически загружается ~20МБ ONNX-моделей.

## Отказ от ответственности

Проект предназначен только для технического обучения и общения. Скрипт работает через симуляцию касаний
ADB; он не изменяет файлы игры, не читает/не пишет игровую память и не вмешивается в сетевые соединения.
Пользователь несёт все последствия использования средств автоматизации, включая, но не ограничиваясь,
риском для учётной записи. Соблюдайте условия обслуживания соответствующей игры.
